# 案卷（anjuan）Windows 本地多人版 PRD

版本：0.3（外部审阅通过后的非阻断补充）。日期：2026-11-03。Phase 0 业务方案及技术文档已验收通过；本稿补明确通知隔离、普通界面配置读取和 Git 保护，不表示功能已实现，也不授权 Commit/Push 或开始 Phase 1。

## 1. 产品目标与使用边界

案卷基于案齐 v2.12.6 固定提交开发。一台 Windows 电脑、一套本地业务服务、一套 SQLite 和案件文件目录，支持多个应用账号独立登录，所有启用账号可查看全部案件。核心业务离线可用。首版包括案件登记、程序进度、期限、文件、精简律师费、身份权限、审计和统一备份恢复。

本地多人不包含不同电脑同步，不把 SQLite 放入 SMB、网盘同步目录来实现协作。首版不开放局域网业务访问，不提供远程连接配置，不开发公司服务器部署。将来提供浏览器和桌面共用远程 API 的条件，见报告 05。

首版**仅支持同一 Windows 系统账号环境内切换应用账号**，不支持多个 Windows 系统账号共享同一服务。并发一致性通过隔离 Cookie 的测试客户端连接同一测试后端验证，不据此承诺多桌面窗口或多电脑访问。[A15、A18]

## 2. 固定角色与权限矩阵

首版固定管理员、编辑人员、只读人员三个角色，提供用户管理、角色分配和权限说明，不开发自定义角色编辑器。独立审阅页见[角色权限矩阵](角色权限矩阵.md)。

| 操作 | 管理员 | 编辑人员 | 只读人员 |
|---|---|---|---|
| 查看全部案件、进度、期限、日志、联系人、案件文件 | 是 | 是 | 是 |
| 预览和下载单份案件文件 | 是 | 是 | 是 |
| 新建和编辑案件、事件、期限、待办、日志、联系人 | 是 | 是 | 否 |
| 上传文件、添加或解除附件引用 | 是 | 是 | 否 |
| 删除事件、期限、待办、日志、联系人等业务记录 | 是，留痕 | 是，留痕 | 否 |
| 案件软删除、文件本体删除及其恢复 | 首版不提供 | 首版不提供 | 首版不提供 |
| 查看精简律师费五项信息 | 是 | 是 | 是 |
| 新建/修改约定金额、折扣、折扣后金额、付款状态、备注 | 是，留痕 | 是，留痕 | 否 |
| 查看自己的通知、标记自己已读、修改本人密码 | 是 | 是 | 是 |
| 读取普通业务界面最小必要的脱敏配置 | 是 | 是 | 是 |
| 创建/停用账号、重置密码、分配角色 | 是 | 否 | 否 |
| 全量审计、系统配置、统一备份与恢复 | 是 | 否 | 否 |
| 复杂财务、分账、结算及其历史管理接口 | 关闭 | 关闭 | 关闭 |
| AI、LegalRAG、IM、CLI 静态 Token、内部自动化 | 关闭 | 关闭 | 关闭 |

所有启用账号共享案件可见范围。账号、系统管理与审计权限独立于案件读取。复杂模块的代码和历史数据保留，界面隐藏，服务端接口也拒绝访问，管理员不能仅因角色为 admin 绕过功能关闭。拒绝编辑由后端返回 403；未开放功能统一返回明确不可用结果。附件解除引用只删除关联，保留文件本体；不把统一备份恢复列入暂缓的案件/文件删除恢复功能。

## 3. 核心流程与需求

| 编号 | 流程/需求 | 首版目标 | 可验证完成条件 |
|---|---|---|---|
| FR-01 | 首次启动 | 选择本地数据目录，初始化唯一首位管理员，无默认通用密码 | 初始化只允许一次；两个并发请求最多成功一个；重启不重复创建 |
| FR-02 | 登录/切换 | 用户名+密码登录，显示当前账号和角色；退出后切换账号 | A 退出后 B 看同一案件；A 的 Cookie 不能因 B 登录获得 B 身份 |
| FR-03 | 人员管理 | 创建账号、停用/启用、重置密码、改角色；保留停用账号历史身份 | 下一次请求和长连接撤销后均不能继续读取/写入；最后有效管理员受保护 |
| FR-04 | 案件登记 | 沿用案齐字段、程序及阶段；基础检索、编辑、结案 | 同一虚构案件在全部角色下可查；编辑被正确授权；历史记录可追溯 |
| FR-05 | 进度与期限 | 保留确定性规则、人工设定、依据和重算确认 | 事件日期/送达方式修改后正确预览重算；人工覆盖不被无声改写 |
| FR-06 | 待办和工作日志 | 首版均为共享业务记录；沿用日历和时间线 | 完成/撤销和编辑留痕；只读账号直接发写请求也被拒绝 |
| FR-07 | 文件 | 分类浏览、原有格式预览、下载、上传；同名不覆盖 | 中文和长路径样本可用；越界、Windows 保留名、ADS、重解析点样本被阻断 |
| FR-08 | 删除范围收敛 | 不提供案件软删除、文件本体删除及其恢复；保留结案、普通记录管理和附件解除引用 | 三角色均不能经遗留或新接口删除案件/文件本体；解除引用不动原件；不得出现未实现的恢复按钮 |
| FR-09 | 提醒 | 所有启用账号接收共享案件提醒；投递记录、展示和已读按真实登录账号分别处理 | A 不能通过请求参数/请求头读取 B 的通知列表、投递记录或流，也不能按 B 的 deliveryId 展示确认/已读；禁用撤销；重启可发现漏发 |
| FR-10 | 审计 | 修改绑定不可变 user_id；派生操作标明 system 及触发账号 | 伪造 actor 请求头不能改归属；修改和审计要么同时成功要么同时回滚 |
| FR-11 | 备份恢复 | 管理员从 GUI 启动，显示阶段/进度/日志；统一包含 DB 与案件文件及必要配置密钥 | 恢复到新目录后账号、案件、附件、审计均可用；失败保留原数据 |
| FR-12 | 安装更新 | Windows x64 安装器；版本检查、进度、失败重试、校验和 Release 说明 | 未授权不安装；不完整或校验失败包不可执行；升级保护数据 |
| FR-13 | 离线核心业务 | 未配置互联网服务仍可登录、查改案件、管理文件、使用本地提醒及备份 | 断网完成虚构案件全流程；更新失败不阻塞业务 |
| FR-14 | 精简律师费 | 约定金额、折扣、折扣后金额、付款状态、备注；全部账号可读，管理员和编辑可建改 | 金额按分精确处理；折扣及折后金额一致；只读直调被拒绝；旧分账历史不被改写 |
| FR-15 | 非核心模块关闭 | 隐藏复杂财务、分账、AI 等入口，保留源码及历史数据 | 直接访问读写端点也被拒绝；精简费用响应不夹带分账/结算数据；断网启动不加载可选外部服务 |
| FR-16 | 普通界面配置读取 | Phase 2 核查现有界面依赖，必要时提供服务端白名单限定的最小脱敏读取 | 编辑/只读可正常使用核心界面；不能取得完整设置、密钥、内部路径或关闭模块配置；完整设置仍仅管理员 |

统一备份恢复仍包含在首版。FR-08 是不开放的范围约束，不再预算案件软删除、隔离区和对象恢复的新开发。FR-11、FR-14 等仍需新增或调整实现，不能把上游相近名称当作完成证据。FR-12 参考群聊拾遗流程，用 Electron 实现。[W01–W04]

## 4. 精简律师费规则

复用既有费用与案件关系、金额分单位处理、备注和版本控制；折扣和折扣后金额需要补充，不能把分账比例当作律师费折扣。后端仅接受首版白名单字段，忽略界面隐藏不足以阻止复杂财务请求。[A22]

折扣输入展示方式（折数或百分比）、舍入及付款状态枚举在 Phase 2 开始前给出具体规则并确认。本轮不据此新增分期、付款流水、发票、财务审批或部分付款计算。未填写折扣的历史金额保持原值，不推算原约定金额或补写历史折扣。存在结算/分账保护的历史记录保留原貌，不绕过上游保护直接重写；需要处理时单独报告。

## 5. 共享提醒与独立已读

建议沿用现有提醒默认值作为首版起点：开庭前一天 18:00、当天 07:30；期限提前 3 天、07:30；有到期时刻的待办提前 30 分钟。由管理员配置，全部按北京时间解释。它们是提醒设置，不改变法定期限的确定性计算；具体来源状态过滤和补扫仍须回归验证。[A13]

所有启用账号统一接收案件期限、开庭和共享待办提醒。提醒来源共享，账号投递记录、展示状态、已读状态分别保存；不能用一条全局 delivery 的状态代表所有账号。一个账号已读不代替其他账号已读。停用账号停止投递；启用后的补扫避免重复通知。首版不引入个人待办空间或负责人任务分派，手动案件提醒也共享。

服务端只从有效登录会话取得通知所属 user_id，不接受客户端指定其他账号。列表、历史投递、详情、SSE 首次补发/实时事件、展示确认及已读更新都按该账号过滤；携带他人投递 ID 也不能访问或修改。普通业务通知接口不因管理员身份开放跨账号读取；全量审计继续走独立管理员审计入口。

Phase 2 还要核查普通界面是否调用完整 `/api/settings`，为核心功能确定最小配置白名单；优先复用安全的现有元数据/状态读取，必要时增加最小脱敏读取能力。禁止为兼容界面而向编辑或只读开放完整系统设置。配置写入仍仅管理员，非核心功能关闭策略保持不变。

软件运行时，由本地后端调度，前端通过通知中心和现有 SSE 展示；收到、展示和已读分别记录。软件完全退出或电脑关机期间不能保证准时提醒，应在界面明确说明。重启后补扫上次检查至当前的区间，将已错过提醒列为待处理并展示当前逾期事项；不把“重新发送”当作按时送达。晚到/失败/结果不明应各自可辨识。[A12–A13]

## 6. 数据、并发和安全完成条件

业务更新使用期望版本，冲突返回 409，界面提示刷新后重试，不自动覆盖另一账号修改；多表更新及对应审计同事务。适用于案件、程序事件、期限、待办、日志、联系人等实际可写入口。重算预览也须校验其依据版本，避免确认过期预览。[A03、A05–A07]

用户只能通过登录会话取得身份；停用、改密、重置密码、角色变化后撤销旧会话及流式连接。备份和恢复不能让已撤销的 Session 重新生效。账号名称可变，历史 user_id 不变。所有实际数据修改均需审计，不记录密码、会话原文或文件正文。

应用角色不能防止同一 Windows 用户直接用其他工具读写有权限的 SQLite/文件，这是本地信任边界。首版按应用操作权限和普通本地数据保护设计；若要对本机 Windows 管理员或持有文件权限的人强制隔离，需独立服务/ACL/加密方案另行批准。

## 7. 非目标与验收范围

首版不开发案件软删除、文件本体删除及其恢复、AI 法律分析、文书生成、复杂财务/分账/结算、冲突检索、组织审批、案件级访问隔离、跨 Windows 系统账号共享和多电脑同步。相关代码和历史数据保留，非核心接口服务端关闭；关闭可选功能仍需保证模块导入和打包不破坏核心业务。[A18]

后续云端集中数据库/文件、网页访问和服务器提醒的升级路径明确保留；首版不开发云功能、不部署服务器、不联系 IT。产品名称固定为“案卷（anjuan）”，正式图标及其他品牌素材待补充；本轮只更新文档名称，不修改业务 package、图标或发布配置。

首版按同一 Windows 系统账号环境验收；建议首先验证 Windows 11 x64、普通用户权限、中文用户名/目录和离线运行，Windows 10/ARM64 不自动列入支持范围。Windows 基础构建、原生 SQLite 加载和最小包验证安排在 Phase 1 开始时的技术检查，完整适配与原生验收仍在 Phase 3；本轮不执行构建。性能基准可使用 1,000 个虚构案件、10,000 条事件/期限/日志、500 个测试文件，指标待基线测量后确认。

数据恢复、安装升级和原生窗口操作需人工验收；CLI 或浏览器测试通过不能替代。全部用虚构案件和测试文件；验收前不导入真实业务数据。
