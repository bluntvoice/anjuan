# 分阶段开发、测试及验收计划

日期：2026-11-03，修订 0.3。Phase 0 业务方案及技术文档已验收通过，本轮补充三项非阻断要求，不执行 W0 或 Phase 1。

## 1. 全程关口

每阶段开始先提交目标、范围、风险、测试方案和完成标准，等待用户确认；未经确认不扩大范围。每阶段验收通过后，**Commit/Push 仍需用户明确授权**。本轮文档仅允许后续提交至 `docs/phase0-decisions`；推送完成后先提交 Phase 1（含 W0）的详细实施及验收方案，等待确认，不能自动开工。Release、Tag 和云部署不在本轮授权范围。测试构建、安装、原生验收和正式发布分别报告。

遇到数据保护无法证明、不可复现的权限绕过、需要大规模重构、上游 schema 冲突或不可解释的文件丢失，停止当前阶段并报告。测试失败先定位，不能削弱断言、删测或跳过关键测试取得通过。

保留阶段编号：Phase 1 开始先做 W0 Windows 基础构建/SQLite 加载/最小包检查，迁移前完成最小成套备份演练；随后完成身份留痕与会话撤销。Phase 2 完善全域授权、审计、精简律师费和并发一致性。Phase 3 完成剩余 Windows 适配与原生验收。案件软删除、文件本体删除及对象恢复移出首版；统一备份恢复保留。Phase 1 成品仅供合成数据验收。

## 3. 关键验收场景

| 编号 | 测试场景 | 必须看到的结果 |
|---|---|---|
| AC-01 | 管理员建虚构案件，编辑和只读分别登录 | 同一案件/文件可见，无案件负责人可见范围过滤 |
| AC-02 | 只读直接调用所有写入口，包括 raw 上传、快捷录入、收件箱、提醒 ack、旧模块 | 业务修改拒绝；仅本人改密/阅读状态等明确允许的个人操作成功 |
| AC-03 | 编辑创建/改案和精简费用，尝试管理用户/恢复备份；三角色尝试案件/文件本体删除 | 范围内编辑成功；管理操作拒绝；首版暂缓的删除/对象恢复对所有角色均不可用 |
| AC-04 | A Session 有效期间被停用、改密或改角色 | 后续请求失效；既有 SSE/长流也结束；不存在旧静态 Token 旁路 |
| AC-05 | 请求携带另一用户名的 X-Anjian-Actor | 审计仍记录真实账号 ID；客户端不能指定操作人 |
| AC-06 | 两客户端用相同 version 改期、改精简费用或解除引用；普通记录编辑/删除竞态 | 一方成功，另一方 409/状态冲突；无静默覆盖或错案关联 |
| AC-07 | 程序事件修改，影响多个派生期限；审计或 SQL 故障 | 事件、期限、任务、审计一并成功或回滚；人工覆盖保留 |
| AC-08 | 同名上传；在落盘/登记/审计边界中断 | 不覆盖原件；失败可恢复到明确状态；不产生隐蔽孤儿文件 |
| AC-09 | Windows 保留名、ADS、UNC、大小写碰撞、junction/symlink、目录替换 | 不访问案件根外数据；错误清晰；测试不能通过跳过路径保护解决 |
| AC-10 | A/B 接收同一提醒，A 展示/已读，B 尚未处理；关闭超过 60 分钟后重启 | 投递记录、展示和已读均独立；漏发可发现；不将迟到算准时送达 |
| AC-11 | 备份含数据库与附件，在新目录恢复后启动 | 用户/案件/外键/审计/文件摘要一致；旧会话失效；附件可预览下载 |
| AC-12 | 测试安装包升级，取消、失败、卸载和回退 | 原业务目录保留；不自动开启云访问；无残留后端或错误更新地址 |
| AC-13 | 断网首次启动与常规业务 | 初始化/登录/查改/文件/本地提醒/备份可用；外部服务失败不阻塞 |
| AC-14 | 管理员/编辑录入五项基本律师费；只读查看与直接写入尝试 | 可查看；只有管理员/编辑可建改；折扣/折后金额一致，修改有审计和冲突校验 |
| AC-15 | 任意角色直接访问复杂财务、分账、AI 等端点；检查精简费用响应 | 服务端拒绝；简单费用不泄出/改写复杂模块历史；源代码和历史数据保留 |
| AC-16 | Phase 1 起始执行 W0，普通 Windows 用户启动最小后端并加载打包 SQLite | 有独立构建/加载/退出证据；失败不继续假定 Windows 可用；不视为正式安装验收 |
| AC-17 | Phase 2：A 在查询/body/请求头伪造 B 的 user_id 或携带 B 的 deliveryId，读取列表/历史/详情/SSE，修改展示或已读 | 仅以真实登录会话定属主；不返回 B 的数据，不修改 B 的状态；SSE 补发/实时事件同样隔离，管理员普通通知接口也仅本人 |
| AC-18 | Phase 2：逐页记录编辑/只读对设置接口的依赖，测试必要配置读取、任意 keys 扩取及完整 GET/PUT settings | 核心界面正常可用；仅服务端最小脱敏白名单可读；越界字段不返回，完整系统设置仍拒绝；不能通过兼容豁免扩大权限 |
| AC-19 | 本次及后续文档提交前逐一审查候选文件与暂存区、核对目标分支和 main 引用 | 仅 docs/phase0-decisions；无真实案件/数据库/备份/凭据/未经审查研究材料；main 未改写；没有用户授权不 Commit/Push |

AC-02 的 ack 限于本人通知；所有启用账号接收共享案件提醒，各自已读。AC-03 的暂缓删除不包含普通记录管理或管理员统一备份恢复。费用仅开放五项基本管理，未授权的费用删除、凭证/发票与复杂结算均关闭；不能用 POST 或 admin 身份统一放行。

Phase 2 完成通知属主、隔离所需的数据约束和接口负测；Phase 4 在相同边界上完成所有启用账号投递、展示体验及漏发处理。普通界面配置依赖核查是权限改造的兼容性验收，不新增系统管理功能。

## 4. 测试组织与发布纪律

单元测试覆盖权限映射、密码、时间、版本、路径和状态机；集成测试使用临时 SQLite、临时文件和真实 Express 请求；UI 自动化覆盖登录/角色/冲突提示/通知/备份流程；GUI 仅补齐原生窗口、安装器、系统文件关联及 OS 生命周期。

保留上游 check.sh 的断言和功能目的。本轮发现的路径夹具问题应改成跨平台夹具；symlink 在支持的 Windows runner 验证，并补普通权限 junction 测试，不能删除该安全测试。Node 与 Electron 重建 better-sqlite3 后需分别验证，不能混用成功结果。[T01、A21]

每阶段提交一个证据目录：批准的范围、源码 SHA、环境版本、命令及退出码、失败及修复、测试报告、必要截图、数据安全核对和未验证边界。以结果为准，未运行写“未运行”，静态存在写“源码证实”，测试通过写明测试范围。

版本发布时同步 package/锁文件、Windows 包元数据、README、CHANGELOG、PRD 支持范围和 Actions 输入，Release 文案与应用展示一致。测试构建不创建正式 Tag/Release，不继承上游自动发布目的地。真实发布需额外获批，候选包和对应源码包必须能够互相定位。[W01–W04]

## 5. 分支与公开仓库保护

本轮全部补充继续保留在 `docs/phase0-decisions`，未暂存、未提交、未推送；后续另获明确授权才在该分支提交推送。本轮不向 main 提交、合并、重置、变基或强制推送，也不更换 v2.12.6 固定基线。创建 Fork 的既有 main 保持原状，比本地基线高一个上游提交不代表该提交已获开发基线批准。

长期方案提议：Phase 0 文档获准提交推送后，以该批准提交建立 `develop` 作为集成分支，每阶段使用 `feat/phase1-auth` 等聚焦分支，经阶段验收和明确提交推送授权后再通过受审查的 PR 集成。main 保留为受保护的正式版本分支，禁止直接/强制覆盖，发布前必须审查它相对基线保留的上游差异；不自动将 main 的未发布改动混入 develop。该方案作为 Phase 1 详细计划的一部分等待确认，本轮不创建长期/功能分支、不配置远端分支保护或执行合并。

公开仓库提交前先列出候选路径并逐文件审阅来源和内容，再显式按文件暂存；重新检查完整暂存 diff，范围必须与已批准清单一致。不得暂存真实案件、个人资料、数据库、数据备份、凭据、测试临时数据、未脱敏日志或未经审查的研究材料。原始研究快照与文档备份留在本地排除目录，不能依赖文件扩展名或 ignore 规则替代内容检查。审阅过的公开上游元数据/脱敏验证摘要可列入明确清单，提交前如内容变化必须重新检查。

本轮暂存区保持为空，另对当前准备提交的文档及证据副本作候选范围检查；这不等于已批准未来提交。推送后的下一步仅为提交 Phase 1（含 W0、长期分支方案）的详细实施与验收计划，等待用户确认。
