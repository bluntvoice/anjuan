## 2. Codex 工作量估算

以一名 Codex 主执行者持续推进、使用合成数据和现有测试、不并行派发 Agent 为假设。“工作日”按约 6 小时有效调查、编码和验证计，含常规修复，不含用户等待、审批、证书采购、外部网络故障和长期试用。本表是范围估算，不是交付日承诺，也不是 Token/费用报价。

| 阶段 | 修订后工作包 | 有效工作日区间 |
|---|---|---|
| Phase 0 | Fork/分支准备、业务决策同步及本轮文档验收 | 本轮工作，不计入下列正式开发余量 |
| Phase 1 | W0 Windows 基础验证 + 认证/初始化/迁移/人员/会话回归 | 5–8（含 W0 约 1–2） |
| Phase 2 | 全域授权/审计/并发/文件一致性、精简律师费和复杂接口关闭 | 5–9 |
| Phase 3 | 其余 Windows 运行/安装/更新与原生验收 | 4–7 |
| Phase 4 | 共享提醒/独立已读、漏发、统一备份恢复与稳定性 | 4–7 |
| Phase 5 | 精简范围集成、安装升级、文档与发布准备 | 3–5 |
| Phase 1–5 合计 | 从批准开工到发布准备 | **21–36**（约 126–216 有效小时） |

按已识别的原生模块、旧财务耦合和备份一致性风险预留约 20%–30% 弹性，保守规划区间为 **26–47 个有效工作日**。小时仅为按每天 6 小时换算，非基于本项目历史吞吐测量的精确承诺；不据此给出日历完成日期。用户每阶段验收、认证授权和外部工具等待另计。

与上一版 25–44 日相比，移除了案件软删除/文件隔离/对象恢复及其集成验收，缩小复杂财务适配范围；新增五字段律师费及历史保护适配，不能把全部费用工作直接扣除。W0 只是前置分配，已从 Phase 3 扣回，未重复计时。统一 GUI 备份恢复、全域授权和回归仍保留，所以工作量不会随界面项数量同比下降。

不含跨 Windows 系统账号服务、自定义角色、Office 全格式预览/OCR、正式签名证书及素材制作、云端部署。正式图标和品牌素材待用户补充；现有上游图标可留在源码历史，但不能把其存在当作案卷最终发行素材已就绪。
