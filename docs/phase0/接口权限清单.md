# 案卷首版接口权限清单

版本：0.3，2026-11-03。Phase 0 文档已验收通过，本稿补明确通知读取隔离和普通界面配置读取；尚未改造接口。以下为上游 v2.12.6 的 16 个 Router 文件、131 条显式声明，路径包含 server.js 挂载前缀。

所有启用账号查看全部案件、文件和精简律师费；管理员/编辑可改五项基本费用，只读不写。复杂财务、分账、AI、IM、LegalRAG、静态 Token 和内部自动化对所有角色关闭，保留代码和历史数据。不能仅隐藏按钮或把 admin 作为功能关闭的豁免。

当前源码中的 11 个费用声明仅 4 个列为简单费用改造入口：2 个读取、1 个创建、1 个更新；其余 7 个和 shares.js 全部 13 个声明关闭。允许的是改造后的有限行为，绝非授权原端点的全部旧语义。

GET 也可能有副作用；提醒维护归系统调度。提醒来源共享，通知投递记录、展示和已读状态按真实登录账号独立；列表、历史/详情、SSE 首次补发和实时事件均限本人，客户端指定其他 user_id 或 deliveryId 不能跨账号访问。案件软删除、文件本体删除及对象恢复首版不开发；统一备份恢复保留管理员权限。

Phase 2 核查普通业务界面对设置/元数据/状态读取的依赖。`ui.config.read` 仅表示服务端固定白名单的最小脱敏配置能力，具体字段及复用接口由依赖核查确定，不表示已经新增接口；完整 `GET/PUT /api/settings` 仍仅管理员。不得通用 keys 查询、透传全部 settings 或以兼容为由降低完整设置权限。

静态提取不等于运行时覆盖：实际挂载、隐式 HEAD、静态资源、健康检查和动态注册在 Phase 2 比对。cases.read 的返回体须投影非核心字段，防止从案件详情、总览、统计、摘要或通用搜索旁路读到关闭模块的数据；通用案件文件仍遵循全部账号可读，不新增财务文件级隔离。

## 新增端点及请求字段

首次初始化一次性；用户/角色分配、审计、系统设置、统一备份恢复仅管理员；本人改密/已读仅本人。精简费用仅接受约定金额、折扣、折后金额、付款状态、备注及必要的记录定位/版本元数据，服务端拒绝分账/结算等额外操作字段；返回不夹带复杂结算历史。对象删除/恢复不新增端点。所有新入口纳入三角色直调和关闭功能负向测试。

通知详情/投递历史如需独立路由，同样要求 `notifications.self.read`，不能以账号由客户端传入作为授权。普通界面最小配置读取如需补充路由，必须按依赖清单审查固定字段白名单；配置写入和完整系统设置仍要求 `system.manage`。上述为 Phase 2 授权/验收约束，本轮不新增业务端点。
